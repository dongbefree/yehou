# 页后 · After the Page

> 读完一本书之后，真正留下的东西，从来不是书的目录。

把今天读过的内容投进来，它替你留住要点；第二天打开，先读一份昨日简报。

这是一个**自用的深度阅读「消化—回顾」工具**：粘贴长文，自动产出结构化摘要；跨篇串联成当日简报；次日打开，自动补写昨日回顾。

---

## 为什么做

我晚上读完书很累，没有精力再去整理。我希望有个东西替我把今天读的东西压一压、留个底；第二天早上开始读之前，先给我一页「昨天读过了什么」，这样我才接得上。

大多数笔记工具只做「存储」，不管「消化」。页后只做一件事：把当天零散的输入，压成明天还能接着想下去的东西。

---

## 它长什么样

打开后有两页：

- **今日**：粘贴正文 → 「读一遍」→ 得到一张卡片（摘要、核心论点、关键概念、原话、待解疑问、主题标签）。右侧有连续天数、今日字数统计，以及「收束今天」按钮。
- **档案**：每一次收束，都按天留一份简报在这里。

简报不是罗列，而是找线索：这几段阅读之间哪里呼应、哪里打架、有什么没消化完、明天该从哪儿接着读。

---

## 怎么用

1. 用微信或邮箱验证码登录（记录按账号隔离，只有你能看到）。
2. 在「今日」页粘贴今天读的正文，填标题，点「读一遍」。
3. 一天结束时点「生成今天的简报」。
4. 如果忘了点也没关系：第二天打开，它会自动把昨天补写成简报。

---

## 怎么跑起来

### 前端（静态）

```bash
# 任意静态服务器即可，例如：
python3 -m http.server 8080
# 然后打开 http://localhost:8080
```

页面本身是纯静态的（`index.html` + `styles.css` + `app.js`），没有构建步骤。

### 后端（云服务）

本应用依赖 WorkBuddy 云服务提供的三类能力：

- **数据库**：托管 PostgreSQL，两张表（`readings` / `briefings`），开启行级权限（RLS），按 `owner_id = auth.uid()` 隔离。
- **登录**：邮箱验证码 + 微信 OAuth。
- **大模型**：免密钥调用，流式输出 + JSON 结构化输出。

`app.js` 顶部的 `PUBLIC_CONFIG` 里的 `endpoint` / `oauthRelayBaseUrl` / `publishableKey` 是**公开可安全暴露**的配置（`publishableKey` 不是服务端密钥，只用于标识应用与初始化 SDK，真正的鉴权走登录会话）。换到自己的环境时，把这几个字段替换成你自己的云服务下发的值即可。

数据库结构见 `docs/schema.sql`。

## 架构

```
浏览器（index.html / app.js）
   │  粘贴正文
   ▼
「读一遍」 ──► 大模型（流式 + JSON 结构化输出）
   │  摘要/论点/概念/原话/疑问/标签
   ▼
托管 PostgreSQL（readings 表，RLS 按用户隔离）
   │
「收束今天」 ──► 大模型 ──► briefings 表
   │
次日打开 ──► 自动补写昨日简报
```

## 我做的取舍（砍掉了什么，为什么）

- **砍掉标签体系、管理后台、社交分享**。只保留「投入 — 消化 — 次日回顾」这一个闭环。多一个功能就多一份要维护的心智，而我只要这一个闭环。
- **不做「收藏/归档原文全文」**。原文在别处有，这里只存结构化后的要点。
- **每天最多一份简报**。简报的意义在于「第二天早上只读一页」，多了就失去价值。
- **不硬编线索**。简报的 prompt 明确要求：几段内容之间确实没关系，就诚实说没有。约束模型比让它自由发挥更重要——假的洞察比没有洞察更糟。
- **前端单文件、零构建**。这个体量的工具，引入框架和打包器是负资产。

---

## 已知限制（诚实列出）

- 正文超过 24000 字会被截断（`MAX_CHARS`），超长文章只会读前一部分。
- 依赖 WorkBuddy 云服务的模型与数据库；模型按积分计费，不是零成本。
- 登录和数据库操作必须跑在**发布后的 HTTPS 域名**上，本地预览无法登录（来源校验）。
- 没有搜索、没有导出、没有多设备同步之外的协作能力——这些是有意不做，不是遗漏。
- 摘要质量取决于所接入模型的水平，个别长难文本可能读偏。

---

## 技术栈

- 原生 JavaScript（单文件，无框架、无构建）
- 托管 PostgreSQL（行级权限 RLS）
- 免密钥 LLM 调用（流式 + JSON 结构化输出）
- 微信 / 邮箱验证码登录
